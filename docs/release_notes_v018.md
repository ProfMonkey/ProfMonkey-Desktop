> 独立开发分支：`feature/v018-monkey-history-evolution`，从 v0.17 专用分支继承。**未修改 main、未创建 PR、未启动 GitHub Actions、未构建 Windows EXE。** 所有提交使用 `[skip ci]`。

## 机制：真正让过去改变新事件

v0.17 的四条连续案件是 **历史前置条件**，而不是在新界面随意编写的文本。后续新增五个一次性事件：

| 后续事件 | 来自哪段历史 | 可选道路 |
|---|---|---|
| 🍌 第二次仓库会议 | 午夜香蕉失窃案三章全部完成 | 共管钥匙 / 秘密警戒 |
| 🔭 星图的第二个坐标 | 银河信号三章全部完成 | 公开复核 / 秘密研发 |
| 🎉 庆典后的第一条传统 | 广场庆典三章全部完成 | 全民登台 / 精英演出 |
| 🧪 事故后的安全复盘 | 实验室事故三章全部完成 | 透明审计 / 高风险研究 |
| 🏛️ 猴山共同宪章 | 上述多个历史节点 + 法令 + 两猴信任 | 公开议事 / 精英决断 |

四条前置案卷必须由**已建造的对应建筑**解锁，不能从无中生有。v0.17 已经结案的存档无需重玩。

**后续有后果：** v0.17 的旧结局如果是和解，选择合作共享时下一事件额外声望 +1；如果是混乱，选择秘密/精英处理时声望再 -1。后续选项还会改变游戏内香蕉、科研、声望以及出场两只猴子的关系。

第五件「猴山共同宪章」需要同时满足：

1. v0.17 四案中至少 **3 案结案**；
2. 至少 **2 件历史后续事件完成**，且其中至少 **1 次选择合作共享**；
3. 猴山已通过且当前仍有效的至少 **1 项自治法令**；
4. 两只选中的起草猴子之间，**好感 ≥6 且信任 ≥8**。

已经生效的历史不会因以后废除法令而被擦掉，但尚未领取的共同宪章会重新检查前提。

## 新的文明纪元

- 0：🌱 萌芽（尚无建筑）
- 1：🏗️ 建设（至少一座真实建筑）
- 2：🗞️ 城市记忆（至少一件 v0.17 事件结案）
- 3：📚 制度萌芽（至少完成两次 v0.18 后续事件）
- 4：🏛️ 猴山共治（完成共同宪章）

纪元是当前保存的**虚构里程碑**，不使用系统日期冒充历史年代，也不会后台自动推动进度。

## Windows GUI 操作

桌面右键 / 系统托盘 → **「📜 猴山历史 · 文明演化与新事件」**，或 v0.17 城市连续案卷中的 **「📜 查看后续历史」**。

1. 选择后续事件、两只猴子和本次抉择；
2. 阅读三幕故事；第三幕后再次点击「完成并结算」；
3. 游戏再次核查条件和资源余额；成功后保存一次选择。

关闭弹窗、中途取消或资源不足，不会提交本次事件；已经完成的事件只能回看，不能反复刷资源。

新的事件存入原有 **`expeditions.json`** 的 `legacy_events` 字段（最多 5 条固定 ID + 路线）。老存档读取时自动获得空列表。写入**资源 + 历史**使用同一个文件的原子替换；写入失败会回滚内存更改。猴际关系仍在 v0.17 原有的**独立** `relationships.json` 中，关系记录发生在城市结算之后，不具有与城市文件的跨文件原子性。失败时 GUI 会提示用户。

原有 `newspaper()` 猴山日报增加文明纪元及最近三次历史抉择；清空探险档案只删除对应城市故事/演化记录，保留独立人物关系与议会法令文件。

## 验收现状（不使用 GitHub Actions）

新增 `tests/test_v018_city_evolution.py`，涵盖：

- 旧存档兼容，原案未结案不得启动后续；
- 四种后续事件各只能结算一次；
- 历史和解/混乱导致不同资源结果；
- 共同宪章多条件门控，法令撤销或关系变化后的二次检查；
- 伪造结算值、重复请求、资源不足拒绝；
- 本地写入失败时资源/历史原地回滚；
- 未知/重复保存项清洗；清空数据隔离。

推荐在有项目源码、Python 和 pytest 的本机手动执行：

```bash
python -m pytest -q tests/test_v018_city_evolution.py tests/test_v017_city_life.py
```

若能安装 PySide6，再以离屏环境测试 Qt 对话框，并最后在真实 Windows 10/11 上验收。**GitHub 分支远端没有运行以上测试，也没有已验收安装包。**
