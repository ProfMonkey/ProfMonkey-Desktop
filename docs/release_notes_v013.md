# 🐒 ProfMonkey Desktop v0.13 — 猴山议会与动态合作小组（开发候选）

> 基于 v0.12 源码候选分支，不代表 v0.10 丢失的六猴像素动画资源已恢复，不是 Windows 真机验收过的正式版。

## 这次已经写入代码的功能

**三猴以上的真人工触发议会**：右键猴子 / 托盘 →「🗳 猴山议会 · 三猴投票与合作网络」。
由用户手动选择议题，再勾选 3～6 只可见角色。不会擅自启动自动议会、监测电脑活动或者改变用户真实系统设置。

议题有三种：
- 🍌 香蕉配给条例：是否平均分配猴山香蕉；
- 🌙 猴山静音公约：晚上是否禁止大声敲设备；
- 🚀 火箭试飞许可：发明猴的火箭是否批准试飞。

每只猴子拥有自己的虚构立场。系统根据 **个性设定、好感与信任、竞争关系** 计算支持 / 反对 / 弃权。投票是确定性的，同样的猴子和关系会得到同样结果；其中过半数支持则通过，过半数反对则否决，否则暂时僵持。完全是 **角色世界里的表决，不执行任何真实电脑权限、网络或文件操作**。

## 三幕动画，多名角色各自说话

每场会议按照「提出议题 → 每只猴子投票 → 宣布结果」三幕进行。
跟原先第一只与第二只角色抢所有台词不同，**3～6 位参会者都分别显示自己的动作和台词**，其余猴子可以独立待机。

**只有第三幕正常结束，才会真正更新猴际关系**：
- 两只猴子投票一致：小幅增加好感与信任；
- 投票相反：增加一点竞争值；
- 弃权：不罚、不强制表态。
- 拖动、隐藏、暂停、专注、返回安静模式、缩减成员等都会取消未完成的会议，关系不会发生变化。
- 在专注、已有短剧、香蕉竞速时，议会不可强制启动。

## 动态合作小组

不搞永久锁定或随机派系。只有关系档案中 **好感≥35、信任≥30 且竞争<55** 的两只猴子才有强合作边。通过相互关系连接的合作群形成小组；某关系恶化时，下一次预览会自动重新计算社交网络。

议会结果会真正影响后续人际关系，从而影响 v0.11 的偶遇事件、v0.12 的连续剧情结局与之后的合作小组。
**虚构议案现在只是角色立场与关系影响机制，并不是可控制桌面、文件或软件的自动化政策。**

## 性能与兼容性修补

多猴在**默认静音**时不再为每只猴子预先创建 5 个 QtMultimedia 音效播放器；只有用户实际打开声音时才按需初始化，关闭声音或删除猴子时释放播放器。这也用于降低 Windows 离屏回归测试中的本地音频初始化负担。

在 Windows CI 中新增共享的 Qt 测试会话与显式 Qt 对象清理；Qt 离屏通过并不代表真实 Windows 透明窗口交互已验收。
