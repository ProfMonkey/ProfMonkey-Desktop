## 真实资源消费与安全性

所有资源余额与建筑所有权都保存在原本 v0.15 的 `expeditions.json` **同一份本地文件中**；不会出现建筑记录和扣款记录分裂成两个文件的中途不一致问题。创建时再次核查资源和建筑前置条件，经用户确认后一次性扣款、一次性写入。

- 重复建造、资源不足、缺前置建筑、非法名称不收费。
- 如果本地写盘出错，内存余额和建筑状态会回滚；不显示幽灵建筑。
- 旧 v0.15 存档里没有 `buildings` 字段也能正确加载，原资源、猴子出勤、事件记录不会重置。
- 非法 / 损坏的建筑所有权不会授予高级实验室。
- v0.15 已解锁的成果不会因为建造支出导致突然从成果面板消失。

## 建筑与后续探险真正联动

在 v0.15 三幕小队出发时，同时固定 **（1）猴山法令，（2）当时已建城市建筑** 两套快照。建筑加成会参与队伍分数和资源奖励计算。任务中途建设不会修改正在播放的结果；只有之后出发的任务才享受新建筑福利。

例如皮猴与发明猴在香蕉侦察原本可能只是「差点成功」；建好香蕉仓库后，同一支队伍可能因为 +1 协作转为「大功告成」，并额外获得香蕉。再加上经议会批准的香蕉共享条例，加成还可继续叠加。

## 真的出现在 Windows 桌面

新建筑可以通过城市管理局手动展示成**独立可拖拽的 Qt 桌面道具**：香蕉仓库、望远镜、广场、联合实验室。

- 只能展示真正建成的建筑；不能绕过资源消耗提前摆放。
- 同一座建筑已经在桌面则复用现有窗口，不会无限复制。
- 点击时附近空闲猴子会展示专属动作与角色台词；
- 展示只占用已有桌面道具配额（8件），不进行系统操作、屏幕截图或鼠标自动点击；
- 若用户主动清空探险档案（包含建筑所有权），所有已展示建筑道具会一起撤下，普通免费家具保留。
- 建筑所有权持久化；装饰道具的桌面坐标本轮未持久化，重启后可以从城建面板再次摆放。

## 网页交互演示

独立离线 **`site/civilization.html`** 提供四个城区、资源栏、建造按钮、前置条件、文明升级效果和历史。可按「模拟完成探险」增加示范余额再尝试建造；**它只存在浏览器页面内存，不会污染或同步真实桌宠存档**。刷新即可重新开始。
