## 0. 一页读懂：我们到底要做什么

**一句话定位**：一只原创的、住在 Windows 桌面上的教授猴。它会散步、睡觉、吃香蕉，观察鼠标和输入节奏，偶尔制造有前因后果的荒诞事故；用户能逗它，但它不会妨碍正常工作。

**主要参考案例**：BongoCat（输入反馈）、Desktop Goose（调皮整活）、Shimeji/eSheep（自由漫游、碰撞与分身）。**我们不只是“猫换猴”**；核心卖点是：**行为状态 + 事件因果链 + 可控的搞怪频率 + 可分享的短故事**。

**核心体验验收**：第一次打开 10 秒内看见猴子；1 分钟内发现它会自主行动；鼠标逗它有反馈；若继续观察几分钟，有机会遇到一段完整小事故；整个过程中随时可以暂停、拖动、退出，并且不会被抢走工作焦点。

**开发原则**：先能跑，再像活物，再好笑，最后可传播。**每个阶段必须可演示、可测试、可回退**；不能为了新增功能破坏透明、流畅、可退出三条底线。

### 0.1 版本范围

- **v0.1 核心闭环（必须先完成）**：透明窗体、原创猴子、基础动画、自主走动、鼠标互动、物理拖拽、简易行为状态、香蕉事故、设置与退出、Windows 打包。
- **v0.2 有生命感**：输入节奏反应、追逐和躲避、更多姿态、窗口/屏幕边缘攀爬、复杂互动、安静模式与猴山模式。
- **v0.3 荒诞事件和传播**：教授黑板、镜子分身、猴子打架、香蕉道具系统、可配置语录和皮肤、事件重放与安全 GIF 导出。
- **v1.0 可公开发布**：启动与兼容性、多屏和缩放、性能优化、安装与卸载、隐私说明、稳定性测试、README 与演示素材。
- **以后再考虑**：学习计时器联动、成就、可选插件、自定义事件编辑器、其他操作系统。它们不能阻碍 v0.1 上线。

## 1. 产品设计与差异化

### 1.1 目标用户与场景

- 想让电脑有趣一点的学生、开发者和普通桌面用户。
- 长时间学习、写代码、办公期间，允许桌面角落出现一些低干扰的小互动。
- 喜欢截图、动图、短视频分享怪事的人。

### 1.2 和现有桌宠究竟不同在哪

1. **从独立动画升级为因果小故事**：不是随机播“吃香蕉”后立刻播“睡觉”，而是吃香蕉→留下香蕉皮→踩中摔倒→甩锅给用户，每一步依赖上一事件。
2. **从只围着用户转，升级为自主生活**：猴子有“精力、好奇、情绪、调皮程度”，能自己决定散步、偷懒、探索和玩道具。
3. **从强制捣乱，升级为可控恶作剧**：视觉搞怪可以大胆；系统破坏和真抢鼠标不应默认发生。安静模式不弹窗、不夺焦点；猴山模式增加频率，但始终可暂停。
4. **从一次性笑话，升级为可传播的原创猴学世界**：教授眼镜、红领带、荒诞黑板、奇怪台词、事件命名、录制猴子自身透明动画。

**差异化不是已验证的市场优势。** 上述判断需要在小规模测试中验证：用户是否愿意持续开启、愿意主动分享、是否觉得打扰。

### 2.1 已承诺的具体“整活桥段”

- **香蕉危机**：吃香蕉→随手扔皮→自己踩中→摔倒→举牌“都是你的问题”；分支：皮被收走，事故取消。
- **键盘暴走**：输入频率升高→小猴搬出键盘→疯狂敲击→键盘坏掉→拿香蕉继续敲。
- **鼠标报复**：用户反复戳猴子→猴子追着虚拟光标跑→扔香蕉贴图；**不强制移动真实鼠标**。
- **镜像事故**：猴子照镜子→分身出现→互相模仿或打闹→分身退场。
- **教授的尊严**：戴眼镜→掏黑板→写“1 + 1 = 3”→用户点击后改成“1 + 1 = 猴”→鞠躬。
- **边缘坠落**：爬屏幕边缘→脚滑→落地→呆住→假装无事发生。
- **摸鱼/庆祝（后续）**：学习计时器完成后鼓掌；只有用户主动开启任务联动时才响应，不擅自读取浏览记录。

## 3. 用户体验规范：既能整活，又不能烦

### 3.1 两种模式

**安静模式（默认）**：低频散步、睡觉、眨眼、吃香蕉；不夺输入焦点、不主动弹系统窗口、不动真实鼠标；偶发事件需有冷却时间。作为长期常驻模式。

**猴山模式（可选）**：增加跑步、追逐、道具、荒诞事件与分身概率；仍受频率上限、暂停、专注/全屏避让约束。

默认参数作为**试验初值**，需在真实测试中调整：安静模式主动短事件平均间隔约 8～15 分钟；猴山模式约 3～6 分钟。同一完整事件不得重叠；每次事故一般 5～20 秒。

### 3.2 操作方式

- **左键单击猴子**：随机反馈；连续点击存在生气/装死的状态变化。
- **按住拖拽猴子**：移动位置，松手按投掷速度落回可见区域；具有边界保护。
- **右键菜单**：安静/猴山、暂停、尺寸、音效、整活频率、置顶、关于、退出。
- **托盘图标**：恢复显示、暂停/继续、设置、退出（任何时刻可用）。
- **组合快捷键**：仅在确有必要时引入，避免与 IDE 或游戏冲突；不得作为唯一退出方式。

### 3.3 体验红线

1. **不读取/保存具体按键文本、剪贴板内容、密码或浏览历史。** 输入联动只保留匿名计数或频率，而且是可选权限。
2. **默认不强制移动鼠标、不控制别的窗口、不修改文件、不改变桌面图标。** 整蛊仅发生在我们自己的透明渲染层。
3. **不能挡住正常工作**：透明区域尽量点击穿透，角色可收起/隐藏；不得频繁抢焦点。
4. **必须有明显的退出、暂停和静音入口**；开机自启默认关闭。
5. **无联网必要则完全离线**；没有用户明确授权不做桌面录屏或上传。

## 4. 原创美术与动作资源规范

**角色基础设定**：不照搬猫、鹅或现有著名动漫角色。圆润 2D 像素风/卡通风二选一；教授眼镜、红领带、略显欠揍但不吓人的面部表情。建议首版画布 256×256 透明 PNG，以逻辑尺寸约 110～140 px 显示，可缩放。

**制作顺序**：先一张统一角色设定图→统一的前/侧视比例与轮廓→最小动作集→道具→复杂剧情。

**首批必备素材**：`idle`、`blink`、`walk`、`turn`、`sleep`、`wake`、`eat_banana`、`slip`、`fall`、`get_up`、`angry`、`dragged`；道具 `banana`、`banana_peel`、`sign`。可以先用占位色块打通引擎，但 v0.1 对外测试前须替换成统一原创素材。

**后续素材**：爬墙、追鼠标、键盘与碎键盘、镜子/分身、书/黑板/粉笔、眼镜切换、西装/熬夜皮肤、表情泡泡、音效。

**动作资源约束**：每个动作明确帧数、帧率、碰撞框、基准锚点、是否循环、可否中断、结束转移。动画结束必须返回可恢复的状态，不能悬浮卡死。

## 5. 技术选型和程序结构

**第一阶段平台**：Windows 10/11；优先适配常见笔记本。不为跨平台牺牲 v0.1 体验。

**建议原型技术栈**：Python 3.12（或已验证的稳定兼容版本）+ PySide6 + Qt 定时器/事件循环 + Windows API（仅在确有必要时）+ JSON 设置 + PyInstaller。将“行为逻辑”和“窗口实现”隔离，为未来迁移至 C#/Tauri 保留空间。

**模块边界**：

```text
profmonkey-desktop/
├─ app.py                    # 启动与异常恢复
├─ core/
│  ├─ state.py               # 猴子状态与状态机
│  ├─ behavior.py            # 行为选择、冷却与权重
│  ├─ events.py              # 因果事件编排/事件队列
│  ├─ physics.py             # 坐标、速度、碰撞
│  └─ clock.py               # 帧时钟和节流
├─ ui/
│  ├─ overlay.py             # 透明窗体/命中与穿透
│  ├─ tray.py                # 托盘和右键菜单
│  └─ settings_dialog.py     # 设置界面
├─ adapters/
│  ├─ input_activity.py      # 可选：输入活动统计，不采集内容
│  ├─ screen_info.py         # 屏幕/DPI/多屏
│  └─ window_info.py         # 可选：窗口边界识别
├─ assets/
│  ├─ monkey/                # 动作帧与manifest
│  ├─ props/                 # 香蕉、镜子、黑板等
│  └─ audio/
├─ config/defaults.json
├─ tests/
│  ├─ test_fsm.py
│  ├─ test_physics.py
│  ├─ test_events.py
│  └─ test_config.py
├─ README.md
└─ requirements.txt / pyproject.toml
```

**窗口实现风险，须最早验证**：Qt 的透明窗口不等于“角色区域可点击、其他像素必然穿透”。Windows 可能需要原生窗口命中测试或独立交互层。**在第一阶段专门做技术探针，未验证前不承诺完美穿透。** 不宜直接用全局 `WS_EX_TRANSPARENT` 使整只猴子无法拖动。

**系统设计建议**：固定逻辑更新（如 30 Hz）+ 按需绘制；动画帧用时间增量推进；事件/行为逻辑不直接操作 UI；外部输入只传简化事件（鼠标位置、点击、可选活动等级）。

## 6. 按顺序开发：完成一个门禁再进入下一个

> 编号从 P00 开始，**严格按依赖顺序**执行。每阶段的“完成标准”可以直接复制给编码助手做验收。首轮只要求做到 P07，之后再按反馈投入。

### P00｜冻结需求和素材占位（项目准备）

**要做**：建 Git 仓库、README、许可证选择、功能范围与版本约定；建立 issue 列表；确定猴子外观、尺寸、锚点、最小动画清单；准备透明占位图；定义统一坐标单位和目标系统。

**输出**：可运行的空工程、`docs/roadmap.md`、`assets/monkey/manifest.json`、需求清单与版本标签。

**验收**：另一台 Windows 电脑按 README 可完成环境配置；所有后续阶段任务有编号，不在开发时随意增删 v0.1 范围。

### P01｜最小透明桌面窗口（首个技术门禁）

**要做**：用 PySide6 创建无边框、透明背景、置顶/可置顶窗口；屏幕右下角显示静态猴子；托盘图标可退出；窗口透明区域不应遮挡点击；支持 100%、125%、150% 缩放初步检查。

**特别实验**：检查“非角色像素穿透 + 角色像素可拖动”两者同时成立；先尝试 Qt 掩码/命中方式，必要时使用 Windows 原生命中测试。

**输出**：`overlay.py`、`tray.py`、可以一键运行的静态演示。

**验收**：猴子可见，背景真正透明；不出现大黑框；可点击桌面图标/输入到其后方应用；可正常退出；没有焦点闪烁。如果失败，不进入 P02。

### P02｜帧动画与动作管理器

**要做**：读取 PNG 序列或 sprite sheet；播放待机、眨眼、走路、睡觉/醒来、摔倒/爬起；统一锚点与左右翻转；实现动作优先级、循环与中断。

**输出**：`animation_player.py`（可放入 ui 或 core）、动作资源清单、动画测试页。

**验收**：所有动作无闪烁、位置不跳动；动作结束后回到稳定姿态；移动窗口时不影响动画；资源丢失时使用占位动作而非崩溃。

### P03｜二维移动、重力与屏幕边界

**要做**：坐标、速度、地面高度、简单重力、碰撞；站立→散步→转身；跑步；落地、反弹、屏幕边缘保护；窗口被拖到可见区域之外时自动回收。

**输出**：`physics.py`、运动状态、独立物理测试。

**验收**：猴子不会永久离开屏幕；落地不会穿透/无限抖动；运行数十分钟仍能自然移动；多次快速转身不会左右震荡。

### P04｜鼠标互动与抓取投掷

**要做**：角色命中区域点击反应；根据鼠标相对位置调整视线；按住拖拽；记录短时间拖拽速度，松手产生抛物运动；点太多次生气或装死；正确处理异常释放鼠标。

**输出**：点击、拖动、抛掷三类互动；状态和命中测试。

**验收**：拖起/松手自然；点击其他软件不会被猴子误拦截；投掷后回到屏幕内；按 Esc 或失焦不会让猴子永远“抓在手里”。

### P05｜猴子状态机与自主行为

**要做**：精力、心情、好奇心、调皮值；发呆、走路、跑步、睡觉、吃香蕉的决策；加入不可中断动作、动作冷却、加权随机、种子复现、事件优先级；设置空闲阈值。

**输出**：`state.py`、`behavior.py`、`tests/test_fsm.py`。

**验收**：同一随机种子可复现行为序列；不出现“睡着还在跑”“同时吃两根香蕉”；无人操作时能自己活动；动作不过分频繁。

### P06｜第一个因果事件：香蕉事故（产品灵魂）

**要做**：道具层、事件队列、清理机制；实现“吃香蕉→丢香蕉皮→触碰→滑倒→爬起→举牌甩锅”，并设一个不摔倒的分支；事件取消、超时、失败回滚；结束后清理香蕉皮和牌子。

**输出**：`events.py`、`banana_accident` 剧本、事件自动化测试。

**验收**：在可控随机种子下完整重现两个结局；不会重复生成无限香蕉皮；事件中途暂停/退出后无残影；5～20 秒能讲清一个笑话。

### P07｜设置、安静模式、打包和 v0.1 发布门禁

**要做**：设置页和 JSON 持久化；角色大小、置顶、静音、事件频率、暂停/恢复、重置设置；托盘菜单；日志与异常提示；PyInstaller 打包；安装/卸载说明、隐私说明、演示 GIF、简体中文 README。

**输出**：`v0.1.0` Windows 可执行包、Release 说明、已知问题列表。

**验收**：关闭再打开后设置仍在；任意时刻可暂停退出；常见分辨率和缩放下没有遮挡灾难；至少连续运行 2 小时不崩溃；至少 3 位非开发者能安装、玩到香蕉事故并退出。

**到这里就先公开小范围测试，不要为了追加几十个功能推迟发布。**

### P08｜输入活动互动与迷你键盘短剧（v0.2）

**前置**：v0.1 用户反馈可接受；输入采集方式与隐私说明审核完成。

**要做**：只判断短窗口内的点击/按键节奏，按活动等级触发敲键盘、拍桌、看鼠标；高强度输入触发“迷你键盘→敲坏→香蕉继续敲”完整短剧；输入侦测默认关闭或清晰征求同意。

**验收**：不读取、不记录输入文本；密码框/敏感界面可暂停侦测；无权限仍可正常运行；用户暂停互动后不再采集。

### P09｜环境感知：边缘攀爬、任务栏与窗口边界（v0.2）

**要做**：先做屏幕左右边缘攀爬和滑落；再评估 Windows 原生 API 读取普通窗口矩形与任务栏边界；多显示器下限制活动区域；避免对浏览器内容本身做读取。

**验收**：进入全屏软件或窗口布局变化时，不会跑进不可见区域；窗口检测失败有安全降级（只在屏幕边缘活动）。

### P10｜追逐/逃跑、声音与猴山模式（v0.2）

**要做**：鼠标追逐、鼠标靠近逃跑、香蕉贴图报复；给行为设置冷却；小音效和静音；猴山模式提高整活频率但仍有限额；可一键回到安静模式。

**验收**：同一时间只允许一段主事件；音效默认不过响；猴山模式不抢焦点、不改变真实鼠标、不影响正常编辑；全局暂停立即生效。

### P11｜进阶剧情：黑板、镜像、分身（v0.3）

**要做**：实现“教授黑板”“镜子分身”剧本；多猴角色实体、分身生命周期、相遇碰撞、互相追逐与短暂打闹；数量上限（初设最多 3 只）；按事件优先级避免剧情冲突。

**验收**：没有无限繁殖；镜子事件后分身能正确退场；多角色运行时不明显掉帧；任何时间都能统一暂停和退出。

### P12｜猴学内容、皮肤、事件收藏与 GIF（v0.3）

**要做**：猴学台词、用户自定义台词、教授/西装/熬夜/考试周皮肤；事件名称和本地收藏；保存角色和道具渲染轨迹，生成透明背景或纯色背景 GIF；默认不录屏、不包含桌面窗口。

**验收**：用户添加不可信文本不会让程序执行代码；皮肤切换不中断当前操作；导出内容不包含密码框、私人文档、通知等系统画面；关闭收藏后不记录事件。

### P13｜稳定性、兼容性和用户研究（v1.0 候选）

**要做**：多屏、100%/125%/150%/200% DPI、系统睡眠与唤醒、显示器断连、全屏检测、崩溃恢复、性能分析、静默运行行为；请真实用户测试是否有趣/是否打扰。

**验收目标（非保证值）**：空闲 CPU 尽量小于 3%，尽量避免长期高帧率绘制；内存占用持续稳定；4 小时长测无崩溃；退出后无残留后台进程；缩放和切屏不丢猴子。

### P14｜发布、传播与迭代闭环（v1.0）

**要做**：版本号、打包校验、Windows Defender/SmartScreen 误报说明、可验证的下载渠道、开源许可证与第三方清单、简体中文与英文介绍、动图展示、贡献指南、Issue 模板、用户反馈入口。

**验收**：陌生人从项目主页下载到退出可独立完成；软件实际功能与 README 一致；隐私和权限有明确解释；删除或卸载后不残留用户不知情的自启任务。

## 7. 行为系统与事件系统的实现契约

### 7.1 基本状态

- `energy` 精力：0～100；移动消耗，睡眠恢复。
- `mood` 情绪：-100～100；被戳可能变坏，被奖励可能提高。
- `curiosity` 好奇心：0～100；越高越倾向探索鼠标/道具。
- `mischief` 调皮：0～100；越高越可能触发搞怪，但仍受模式和频率限制。
- `mode`：QUIET / MONKEY；`action`：IDLE、WALK、RUN、SLEEP、EAT、DRAG、FALL、EVENT 等。

**动作优先级原则**：紧急收尾/退出 > 用户抓取 > 已开始的不可中断事故 > 普通互动 > 自主行为。不是所有新事件都可以打断当前动作。

**每次决策检查**：角色是否忙碌、当前事件是否冷却、是否有安全空间、是否全屏/暂停、下一动作所需素材是否存在；不满足则回到安全待机。

### 7.2 事件定义示例：香蕉事故

```yaml
id: banana_accident
mode: [QUIET, MONKEY]
trigger: energy > 30 and no_active_story
cooldown_seconds: 600
steps:
  - play: eat_banana
  - spawn: banana_peel
  - branch:
      - when: crosses_peel
        then: [slip, fall, get_up, show_sign_blame]
      - otherwise: [notice_peel, pick_up_peel]
cleanup: [banana_peel, sign]
on_interrupt: cleanup_and_return_idle
```

这个文件仅是**机制示意**，不要求第一天就引入 YAML 解析器。v0.1 可以用普通 Python 类实现同样语义，待剧本数量增加后再数据驱动。

### 7.3 事件记录

开发调试记录：时间戳、事件 ID、随机种子、动作切换、失败原因；默认本地，禁止写入具体按键、页面标题、窗口内容。用户正式运行时日志应可关闭或自动轮转。

## 9. 仓库任务管理与交付规范

**Git 工作方式**：`main` 保留稳定演示，按 `feature/p01-overlay` 等命名分支；每个阶段至少一次可回滚提交；合并前按验收表人工演示，必要时录制软件自身演示画面。

**每个任务 issue 写明**：任务 ID、前置依赖、范围、非目标、输入素材、需要改的模块、手工复现步骤、自动测试、验收截图/视频、已知风险。

**每阶段提交三样东西**：①能运行的程序；②简短变更说明；③当前功能勾选表。只提交“代码量增加”不视为完成。

**常见错误提前防范**：只做 GIF 播放没有行为引擎；窗口透明但透明区域截获鼠标；一段事故卡住所有后续动作；Python 定时器太多造成 CPU 常驻高负载；素材锚点变化使猴子瞬移；分身无限增加；输入监听读取敏感文本；打包后资源路径失效。

## 12. 真正开工时的第一条指令

**不要一次性让 AI 写“完整桌宠”。** 第一次只给开发助手 **P00 + P01**：搭建项目、创建透明猴子窗口、验证透明区域穿透与猴子交互命中、托盘退出；提交程序、运行命令、测试记录与未解决问题。待 P01 验收通过再进入 P02，严格执行此文档的开发门禁。

**一句话总结**：先让它出现在桌面上；再让它能动；再让它像活着；最后让它制造一场真正好笑、可以复现、又不打扰用户的猴山事故。
